# Lyricon 和声逐字转换修复

原修复基线为 v0.9.3，提交
`02f81449ee0b6dba0042bb8ff7a3854aa64c5177`。当前分支已迁移到 v0.9.45，见 [迁移说明](lyrics-v0.9.45-migration.md)。

稳定版原实现只读取 `RichLyricLine.secondary`，创建和声行时把三个逐字数组
全部设为 null。此修改在 Lyricon 接收后的转换层读取 `secondaryWords`，保留
有效的逐字开始、结束时间及重新计算的字符边界。

和声全文和逐字文本中的一对完整外层括号仅在显示副本中隐藏，支持 ASCII
和全角括号。首尾词携带括号、括号独立成词均可处理，不修改收到的协议对象。
内部括号、未配对括号以及正常重复歌词不做全局删除或去重。

全文可以与逐字列表对应时保留全文中的空格；对应不上时，以逐字列表构建
显示文本并保留时间轴，而不是因为文字不同而丢弃有效时间。这样也处理
`(和声)和声` 全文与单份逐字列表的情况。全文缺失但逐字列表存在时仍可显示。

和声行使用自身逐字时间确定边界，必要时延长所属主唱行的结束时间。缺失词尾
时间沿用原有 `closeUntimedTail` 策略。超出内部整数范围或开始时间倒序的
数据不进入逐字渲染；没有可用逐字数据时仍可显示逐行文字。

渲染器分别判断主唱和和声是否具有逐字数组，避免空数组访问，并支持主唱
逐行、和声逐字的组合。布局缓存与持续刷新也检查和声自身的逐字数据。

回归测试：`LyriconBackgroundTest`，13 项，涵盖括号、独立括号词、重复全文、
缺失全文、英文空格、合法重复、内部括号、无逐字数据、时间溢出、缺失词尾、
和声延长及真实 Lyricon 0.1.70 模型的序列化往返。

本机使用独立 JVM 编译生产转换代码与测试，测试通过；仅日志及
`LockLyrics` 常量使用测试占位类。未构建 APK，未验证 Android Canvas 实机
渲染、词幕服务 IPC 或 SystemUI 的运行效果。完整 Android 工程测试命令为：

```sh
./gradlew :app:testDebugUnitTest --tests com.os4.musiccover.lyrics.LyriconBackgroundTest
```
